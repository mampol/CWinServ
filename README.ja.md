# CWinServ (C++17 / UTF-16)

C++17およびUTF-16に対応した、Windowsサービス用の基底クラスです。

## ファイル構成

- `CWinServ.h`, `CWinServ.cpp`：外部の独自ライブラリに依存しない、Windowsサービスの基底クラス
- `Example.cpp`：サービス実行ファイルのサンプル（`wmain`）

## Visual Studio 2022

Windowsコンソールアプリケーション形式のC++プロジェクトに、`CWinServ.h` と `CWinServ.cpp` を追加してください。必要に応じて、サンプルの `Example.cpp` も追加します。

プロジェクトの設定は以下のとおりです。

- C++言語標準：C++17
- 文字セット：Unicode
- リンクライブラリ：`Advapi32.lib`

本クラスでは、`TCHAR` を使用せず、Win32 APIのUnicode版（`W` API）を明示的に呼び出しています。

`Advapi32.lib` はSDKの設定によって自動的にリンクされる場合もありますが、Visual Studioの「リンカー → 入力」で明示的に指定してください。

x64、x86のどちらでもビルドできます。

`Example.cpp` は、サンプルプログラムを作成する場合にのみコンパイルしてください。

### サービスの登録と実行

管理者権限でコマンドプロンプトを起動し、次のコマンドを実行します。

#### インストール
```bat
Example.exe /install
```

#### アンインストール

```bat
Example.exe /uninstall
```

サービスのインストールはWindowsのシステム設定を変更します。適切な管理者権限を持つ、安全な開発環境でテストしてください。

`/uninstall` を実行する場合は、サービスが完全に停止している必要があります。

### サービスの初期設定

デフォルトでは、以前の実装方針に合わせて、次の設定になっています。

- 自動起動（遅延自動起動）
- 異常終了時の自動再起動：3回
- 再起動までの待機時間：60秒

これらの設定は、セッター関数を使用して無効にすることもできます。

## 実装上の注意事項

### サービスのインスタンス管理

本クラスは、1プロセスにつき1つのサービスインスタンスを扱う設計です。

`ServiceMain()` には呼び出し元のコンテキストを渡す仕組みがないため、プロセス全体で共有するatomicなポインタを使用して、サービスインスタンスを管理しています。

複数のインスタンスから `RunService()` を同時に呼び出さないでください。

### サービスの停止処理

- SCMからの制御コールバックでは、停止要求の設定と手動リセットイベントへの通知のみを行います。
  実際のサービス停止処理は、`ServiceWorker()` 側で行う必要があります。
- `ServiceWorker()` は停止要求を確認し、適切に処理を終了して戻るように実装してください。
- `ServiceWorker()` はサービスメインスレッド上で実行されます。
  別のバックグラウンドスレッドを起動する場合は、スレッドを切り離したままにせず、`ServiceWorker()` が戻る前に終了を待機してください。

### WaitForStop()

`WaitForStop()` は、Windowsの待機APIが返す結果をそのまま返します。

主な戻り値は以下のとおりです。

- - WAIT_OBJECT_0：停止イベントが通知された
- WAIT_TIMEOUT ：指定時間が経過した
- WAIT_FAILED  ：待機処理が失敗した

### 一時停止・再開について

本クラスでは、一時停止および再開の制御を意図的に実装していません。

一時停止機能を正しく実装するには、派生クラス側の処理との連携が必要になるためです。

そのため、一時停止・再開の制御要求はSCMに受付可能として通知していません。

現時点では、未対応の制御要求に対しては、`ERROR_CALL_NOT_IMPLEMENTED` を返します。

### 停止要求時のコールバック

`OnStopRequested()` および `OnShutdownRequested()` は、次の条件を守って実装してください。
- 短時間で処理を終了すること
- ブロッキング処理を行わないこと
- 例外を送出しないこと（`noexcept`）

時間のかかる終了処理やリソースの解放処理を、これらのコールバック内で実行しないでください。

### サービスの状態管理

サービスの状態は、停止処理を含む通常の動作で次のように遷移します。

```text
START_PENDING
    ↓
RUNNING
    ↓
STOP_PENDING
    ↓
STOPPED
```

`ServiceWorker()` の終了後に、`SERVICE_STOPPED` をSCMへ通知します。

この最小構成の実装では、停止時に1回のチェックポイント通知と、30秒の待機時間の目安を設定しています。

停止処理が大幅に長引く可能性がある場合は、定期的に `STOP_PENDING` のチェックポイントを更新する仕組みや、停止処理の時間制限に関する方針を追加してください。

### 実行ファイルのパスと引数

- `Setup()` に渡す実行ファイルのパスには、前後のダブルクォーテーションを含めないでください。
- インストール処理側で自動的に引用符を付加します。
- `commandOption` は、コマンドライン引数として整形済みの文字列を渡す仕様です。
- 引数に含まれる空白や引用符などのエスケープ処理は、呼び出し側で行ってください。

### サービス実行アカウント

- `SetupAccount()` は、指定されたパスワードを平文のままメモリ上に保持します。
  このパスワードは、サービス実行アカウントが空でない場合にのみ使用されます。
  可能であれば、Windowsの組み込みアカウントやマネージドサービスアカウントを使用することを推奨します。
- この最小構成の実装では、保持した認証情報をメモリから安全に消去する処理は実装していません。

### 旧クラスの依存機能について

以前の実装に存在した、次の独自クラスは含まれていません。

- `CNamedPipeTh`
- `CWinError`
- `CEvntReg`

これらの実装が提供されていないため、今回のクラスからは除外しています。
なお、今後実装を行う予定です。

- サービスの起動・停止
- Windows起動時の自動起動
- 異常終了時の動作
- アクセス権限による制限
